# پشتیبانی آزمایشی از تاچ GT911 در SmartPendant

> **وضعیت: آزمایشی (Experimental / Hardware not verified).**
> کد حاضر یک Release قابل فلش و تأییدشده نیست. تست‌های Mock روی کامپیوتر موفق بوده‌اند؛ اما کامپایل نهایی STM32، اتصال الکتریکی و آزمایش لمس روی برد واقعی هنوز باید بررسی شوند.

## هدف

در SmartPendant اصلی از کنترلر LCD مدل **ILI9488** و تاچ خازنی **FT6236** استفاده می‌شود. در نمایشگر جایگزین **Z350IT008-DCT** (۳٫۵ اینچ، 320×480) همچنان درایور تصویر **ILI9488** است، ولی تاچ با **Goodix GT911** و فلت **۸ پین با گام ۰٫۵ میلی‌متر** ارائه می‌شود. هدف این توسعه افزودن GT911 **بدون حذف پشتیبانی FT6236** است.

**جایگاه این پوشه:** مخزن `coolboysalam/SmartPendant` یک Fork از پروژه سخت‌افزاری Devtronic است و خودش سورس کامل فریمور را در ریشه ندارد. سورس فریمور در `nickshl/SmartPendant` نگهداری می‌شود. به همین علت، این پوشه یک **Firmware overlay** است: فقط فایل‌های جدید و فایل اصلاح‌شده را نگه می‌دارد و اسکریپت Build آن‌ها را روی یک نسخه مشخص از فریمور اصلی اعمال می‌کند. پوشه‌های PCB و 3D_Print پروژه اصلی دست‌نخورده باقی می‌مانند.

## خلاصه تغییرات

| فایل | تغییر |
| --- | --- |
| `Application/GT911.h` و `.cpp` | درایور GT911 مبتنی بر `ITouchscreen` و `IIic` |
| `Application/AutoTouch.h` و `.cpp` | تشخیص کنترلر FT6236 یا GT911 در زمان راه‌اندازی |
| `Application/AppMain.cpp` | تغییر ساخت شیء `FT6236` به `AutoTouch`، بدون تغییر کنترلر LCD |
| `Tests/host_gt911/` | تست‌های مستقل Mock I²C و GPIO |
| `scripts/build.sh` | دریافت نسخه ثابت فریمور/DevCore، اعمال overlay، تست و Build |
| `../../.github/workflows/gt911-build.yml` | Build آزمایشی در GitHub Actions |

### روند تشخیص خودکار

1. گذرگاه I²C فعال می‌شود و آدرس هفت‌بیتی `0x38` بررسی می‌شود.
2. اگر FT6236 در این آدرس حضور داشته باشد و `FT6236::Init()` موفق شود، **درایور قبلی بدون تغییر** انتخاب می‌شود.
3. در غیر این صورت، توالی Reset/INT برای GT911 اجرا و دو آدرس هفت‌بیتی `0x5D` و `0x14` امتحان می‌شوند.
4. ID کنترلر از رجیستر `0x8140` خوانده می‌شود و انتظار می‌رود با `911` آغاز شود.
5. در زمان لمس، وضعیت از `0x814E`، رکورد اولین نقطه از `0x814F` خوانده و وضعیت آماده پس از پردازش پاک می‌شود.
6. در صورت خطای I²C، وضعیت لمس نامعتبر می‌شود و تابع Reset گذرگاه فراخوانی می‌گردد.

UI فعلی فقط مختصات **اولین انگشت** را استفاده می‌کند؛ بنابراین هرچند GT911 تا پنج لمس را پشتیبانی می‌کند، این توسعه چندلمسی را به رابط کاربری اضافه نمی‌کند.

### نکته خاص DevCore

در `StHalIicThreadSafe::Transfer()`، آرایه دو‌بایتی آدرس رجیستر برای `HAL_I2C_Mem_Read()` به شکل **Low byte سپس High byte** آماده می‌شود، ولی `IIic::Write()` داده‌ها را عیناً ارسال می‌کند و در نوشتن باید **High byte سپس Low byte** ارسال شود. کد GT911 این تفاوت را رعایت می‌کند.

## اتصال سخت‌افزار (قبل از نصب حتماً بررسی شود)

طبق دیتاشیت نمایشگر **Z350IT008-DCT**، ترتیب سیگنال‌های فلت تاچ جدید:

| پایه فلت ۸ پین | نام سیگنال | مفهوم |
| --- | --- | --- |
| ۱ | VDD_3.3V | 3.3V |
| ۲ | RST | Reset |
| ۳ | INT_3.3V | Interrupt / انتخاب آدرس هنگام Reset |
| ۴ | NC | بدون اتصال |
| ۵ | NC | بدون اتصال |
| ۶ | SCL | کلاک I²C |
| ۷ | SDA | داده I²C |
| ۸ | GND | زمین |

در سورس فریمور، پایه‌ها به شکل زیر تعریف شده‌اند: **PB5 = TOUCH_RST**، **PB6 = TOUCH_INT**، **PB8 = I2C1_SCL** و **PB9 = I2C1_SDA**. این اطلاعات فقط تعریف میکروکنترلر هستند و *شماره‌گذاری واقعی کانکتور ۶ پین روی PCB را تأیید نمی‌کنند*.

**هشدار مهم:** تبدیل ۸ پین به ۶ سیگنال از نظر منطقی ممکن است چون پین‌های ۴ و ۵ فلت جدید NC هستند؛ اما جهت کنتاکت فلت (بالا/پایین)، ترتیب شماره‌گذاری سوکت، اتصالات تغذیه، مقاومت‌های Pull-up، و مسیرهای برد باید با شماتیک و مولتی‌متر تأیید شوند. **تا آن زمان نمایشگر جدید را به برد وصل نکنید.**

همچنین **فلت LCD چهل‌پین** باید تک‌به‌تک تطبیق داده شود؛ مشترک بودن ILI9488 به معنی یکسان بودن پین‌آوت LCD نیست. دیتاشیت، محدودکردن جریان LED Backlight به حدود **۱۲۰ میلی‌آمپر** را ضروری دانسته است.

## ساخت فریمور

### GitHub Actions (پیشنهادی)

از تب **Actions** در این Fork، Workflow به نام **GT911 experimental firmware build** را اجرا کنید؛ یا تغییرات را روی Branch ارسال کنید تا Job روی Push/PR اجرا شود. Workflow:

- سورس فریمور `nickshl/SmartPendant` را در Commit مشخص دریافت می‌کند؛
- زیرماژول `DevCore` را در Commit قفل‌شده می‌گیرد؛
- فایل‌های این پوشه را روی سورس فریمور کپی می‌کند؛
- تست‌های Host/Mock را اجرا می‌کند؛
- با ARM GCC و CMake فایل‌های `ELF / BIN / HEX` را می‌سازد؛
- فقط در صورت موفقیت، Artifact آزمایشی منتشر می‌کند.

**فایل Artifact صرفاً برای آزمون است؛ تست سخت‌افزار هنوز انجام نشده.**

### روش محلی (Linux/WSL)

پیش‌نیازها: `git`، `python3`، `c++`، `arm-none-eabi-gcc`، `arm-none-eabi-g++`، `arm-none-eabi-objcopy` و **CMake >=4**. از ریشه همین مخزن:

```bash
bash Firmware/GT911/scripts/build.sh
```

خروجی‌های Build، در صورت موفقیت کامل، در `build/gt911/artifacts/` قرار می‌گیرند. خود اسکریپت بدون فلش یا دستکاری برد اجرا می‌شود.
